WHAT IS PRESIDIO?
=================

Presidio is a data protection and PII (Personally Identifiable Information) de-identification SDK originally developed by Microsoft in Python. It helps organizations:

1. Detect sensitive information in text, structured data, and images
2. Anonymize or redact PII to comply with privacy regulations (GDPR, HIPAA, CCPA)
3. Protect user privacy in data processing pipelines
4. Enable safe data sharing and analytics

The Rust port maintains full feature parity with the Python version while adding:
- Memory safety guarantees
- Zero-cost abstractions for better performance
- Thread-safe concurrent processing
- Strong type system for compile-time correctness
- Multiple deployment options (library, CLI, REST APIs, containers)

CORE CONCEPTS AND DESIGN PATTERNS
==================================

ENTITY RECOGNITION
------------------
Entity recognizers identify specific types of PII in text. Each recognizer:
- Implements the EntityRecognizer trait
- Defines supported entity types and languages
- Uses regex patterns with optional context words
- Returns RecognizerResult with confidence scores (0.0 to 1.0)
- Can be customized via deny lists and validation functions

Example: The EmailRecognizer uses regex to find email patterns, then checks for context words like "email", "contact", or "mail" nearby to boost confidence and reduce false positives.

ANONYMIZATION OPERATORS
-----------------------
Operators transform detected PII. Each operator:
- Implements the Operator trait
- Takes original text and entity location
- Returns transformed text
- Can accept configuration parameters (e.g., masking character, hash algorithm)

The system applies operators in reverse order to preserve text positions, ensuring accurate replacements even with overlapping entities.

CONFLICT RESOLUTION
-------------------
When multiple entities overlap (e.g., an email address within a person's name), the system uses configurable strategies:
1. HighestScore - Keep entity with highest confidence
2. LongestText - Keep entity covering most text
3. MostRecent - Keep the last detected entity
4. PreferredEntity - Prioritize specific entity types

STRUCTURED DATA HANDLING (Phase 9)
-----------------------------------
The StructuredEngine processes JSON documents:
- PathConfig defines which fields to scan (e.g., "user.profile.email")
- Supports nested objects: "person.address.street"
- Supports array wildcards: "contacts[*].phone" processes all contacts
- Applies different operators to different fields
- Returns both anonymized JSON and detailed operation log

YAML CONFIGURATION SYSTEM (Phase 10)
-------------------------------------
Custom recognizers can be defined in YAML without writing Rust code:
- RecognizerConfig defines name, entities, languages, patterns
- PatternConfig specifies regex and confidence scores
- Context words boost scores when found nearby
- Deny lists exclude false positives
- Example: Define a custom ID recognizer for "ABC-123456" format in minutes

EXAMPLE 1: BASIC PII DETECTION
-------------------------------
Scenario: Scan text for email addresses and phone numbers

```rust
use presidio_analyzer::AnalyzerEngine;
use presidio_common::Language;

let engine = AnalyzerEngine::default();
let text = "Contact John at john.doe@example.com or call 555-123-4567";

let results = engine.analyze(
    text,
    Language::En,
    None,  // All entity types
    None,  // No allow list
    0.5,   // Minimum confidence threshold
    false  // Don't return all matches
)?;

// Results contain:
// - EMAIL_ADDRESS at position 17-38 with score ~0.9
// - PHONE_NUMBER at position 47-59 with score ~0.7
```

EXAMPLE 2: ANONYMIZING SENSITIVE DATA
--------------------------------------
Scenario: Replace emails and mask credit cards in customer data

```rust
use presidio_anonymizer::AnonymizerEngine;
use presidio_common::{RecognizerResult, EntityType, ConflictResolutionStrategy};
use std::collections::HashMap;
use serde_json::json;

let engine = AnonymizerEngine::with_defaults();
let text = "Email: alice@company.com, Card: 4532-1234-5678-9010";

// First, analyze the text (from previous example)
let results = analyzer.analyze(text, Language::En, None, None, 0.5, false)?;

// Configure operators per entity type
let mut operators = HashMap::new();
operators.insert(
    EntityType::Email,
    ("replace".to_string(), json!({"new_value": "<EMAIL_REDACTED>"}))
);
operators.insert(
    EntityType::CreditCard,
    ("mask".to_string(), json!({"chars_to_mask": 12, "masking_char": "*", "from_end": false}))
);

// Anonymize
let anonymized = engine.anonymize(
    text,
    &results,
    &operators,
    ConflictResolutionStrategy::HighestScore
)?;

// Result: "Email: <EMAIL_REDACTED>, Card: ************9010"
```

EXAMPLE 3: JSON DATA ANONYMIZATION
-----------------------------------
Scenario: Anonymize user profiles in JSON format

```rust
use presidio_structured::{StructuredEngine, PathConfig};
use presidio_common::{Language, ConflictResolutionStrategy};
use serde_json::json;

let engine = StructuredEngine::new();
let user_data = json!({
    "users": [
        {
            "name": "Alice Smith",
            "email": "alice@example.com",
            "phone": "555-1234",
            "address": {
                "street": "123 Main St",
                "city": "Boston"
            }
        },
        {
            "name": "Bob Johnson",
            "email": "bob@example.com",
            "phone": "555-5678",
            "address": {
                "street": "456 Oak Ave",
                "city": "Seattle"
            }
        }
    ]
});

// Configure which fields to anonymize and how
let configs = vec![
    PathConfig {
        path: "users[*].email".to_string(),
        entity_types: None,  // Auto-detect
        operator: Some(("replace".to_string(), json!({"new_value": "<EMAIL>"}))),
    },
    PathConfig {
        path: "users[*].phone".to_string(),
        entity_types: None,
        operator: Some(("mask".to_string(), json!({"chars_to_mask": 4, "from_end": false}))),
    },
];

let result = engine.anonymize_json(
    &user_data,
    &configs,
    Language::En,
    0.5,
    ConflictResolutionStrategy::HighestScore
)?;

// result.anonymized_data contains modified JSON
// result.operations contains detailed log of all changes
```

EXAMPLE 4: CUSTOM RECOGNIZER VIA YAML
--------------------------------------
Scenario: Detect company-specific employee IDs (format: EMP-123456)

Create config file `employee_recognizer.yaml`:
```yaml
recognizers:
  - name: employee_id_recognizer
    supported_entities:
      - EMPLOYEE_ID
    supported_languages:
      - en
    patterns:
      - name: employee_id_pattern
        regex: '\bEMP-\d{6}\b'
        score: 0.85
    context:
      - employee
      - ID
      - staff
    deny_list: []

settings:
  default_language: en
  default_threshold: 0.5
  enable_nlp: false
```

Load and use:
```rust
use presidio_common::PresidioConfig;

let yaml = std::fs::read_to_string("employee_recognizer.yaml")?;
let config = PresidioConfig::from_yaml(&yaml)?;

// Convert to recognizer and add to registry
for recognizer_config in config.recognizers {
    let recognizer = create_recognizer_from_config(&recognizer_config);
    registry.add_recognizer(recognizer);
}
```

EXAMPLE 5: CLI INTEGRATION IN CI/CD
------------------------------------
Scenario: Prevent commits containing PII

Git pre-commit hook:
```bash
#!/bin/bash
# .git/hooks/pre-commit

# Get staged files
FILES=$(git diff --cached --name-only --diff-filter=ACM)

# Run presidio-cli on staged files
for FILE in $FILES; do
    if [ -f "$FILE" ]; then
        presidio-cli "$FILE" --output github --threshold 0.7
        if [ $? -eq 1 ]; then
            echo "ERROR: PII detected in $FILE"
            echo "Please remove sensitive data before committing"
            exit 1
        fi
    fi
done

exit 0
```

GitHub Actions workflow:
```yaml
name: PII Detection
on: [push, pull_request]

jobs:
  scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v2
      - name: Install Rust
        uses: actions-rs/toolchain@v1
      - name: Build presidio-cli
        run: cargo build --bin presidio-cli --release
      - name: Scan for PII
        run: |
          ./target/release/presidio-cli . \
            --output github \
            --threshold 0.7 \
            --entities EMAIL_ADDRESS,PHONE_NUMBER,SSN
```
